# QUINTET — 五位創作者 × AI 的實作展

**FIVE MINDS. FIVE BUILDS. ONE AI-POWERED JOURNEY.**

這是五位成員以 Claude Code 進行 AI 輔助開發後的作品展覽網站，以「數位藝術展覽 × 互動式作品宇宙」為核心概念。

> ⚠️ 目前五個專案、成員資料與所有截圖皆為**虛構的範例內容（placeholder）**，網站上也有明確標示。請依下方說明替換為實際內容。

## Tech stack

- Next.js 16 (App Router, static prerendering) · React 19 · TypeScript
- Tailwind CSS v4 (tokens in `src/app/globals.css`)
- GSAP + ScrollTrigger (`src/lib/motion.ts` registers plugins once), Lenis smooth scroll
- 2D canvas / SVG / CSS for visuals (no WebGL dependency)
- No backend, no database — all content is local TypeScript data

## 1. Install

Requires Node.js 20.9+ (tested on Node 24).

```bash
npm install
```

## 2. Development server

```bash
npm run dev            # http://localhost:4317 (auto-reloads on save)
```

The cinematic intro plays once per browser session. To see it again, open a new tab/window or clear `sessionStorage` key `avc-intro-seen`.

## 3. Production build

```bash
npm run check:content  # validate src/data (also runs automatically before every build)
npm run typecheck      # next typegen + tsc --noEmit
npm run lint
npm run build
npm run start          # serve the production build
npm run preview        # build + serve on http://localhost:4318
```

All routes (`/`, `/projects`, five `/projects/[slug]` pages) are prerendered at build time.

## 4. Replacing the placeholder projects

All content lives in `src/data/` and follows the types in `src/types/content.ts`. Pages render from data, so you never need to touch components to update content.

| File | Content |
|------|---------|
| `src/data/projects/project-01.ts` … `project-05.ts` | One file per project |
| `src/data/team.ts` | Five member profiles |
| `src/data/program.ts` | Hero copy, mission, journey stages, verified program facts, closing text |

For each project:

1. Edit the fields in its file (`title`, `subtitle`, `category`, `developer`, `summary`, `description`, `technologies`, `features`, …).
2. **Optional sections render only when data exists.** Delete fields you don't have (`architecture`, `challenges`, `results`, `gallery`, `heroVideo`, …) instead of leaving fake values — the corresponding section disappears automatically.
3. **Links:** fill `links.github` / `links.demo` / `links.documentation` / `links.video` only with real URLs. Buttons appear only for links that are set.
4. **Results:** only use verified numbers in `results[].value`; `value` is optional.
5. Set `isPlaceholder: false` and remove `placeholder: true` from media items once the content is real — this removes the "PLACEHOLDER" badges.
6. `accentColor` / `accentColorSecondary` set the project's colour identity across the universe, gallery and detail page.
7. Changing a `slug` changes the URL (`/projects/<slug>`); keep `developerId` and `team[].projectSlug` in sync.

For team members, edit `src/data/team.ts` (`name`, `role`, `bio`, `avatar`, optional `github`) and set `isPlaceholder: false`.

## 5. Screenshots and videos

Put media in `public/projects/project-0N/` (and `public/team/` for avatars), then reference it from the data file by its public path:

```text
public/
├── projects/
│   └── project-01/
│       ├── cover.webp         → thumbnail (universe node, gallery, next-project panel)
│       ├── screenshot-01.webp → heroImage / features[].media / gallery
│       ├── demo.mp4           → heroVideo or a feature media item
│       └── demo-poster.webp   → poster for the video
└── team/
    └── member-a.webp
```

```ts
thumbnail: "/projects/project-01/cover.webp",
heroImage: "/projects/project-01/screenshot-01.webp",
heroVideo: { type: "video", src: "/projects/project-01/demo.mp4", poster: "/projects/project-01/demo-poster.webp", alt: "操作示範影片" },
```

Tips:

- Use **WebP/AVIF**, 16:10 (e.g. 1600×1000) for covers and screenshots. Raster images are optimised automatically by `next/image`.
- Videos lazy-load near the viewport, start muted and always need a `poster`.
- Write meaningful `alt` text in Traditional Chinese.
- Missing or broken files show a styled "Media coming soon" fallback instead of a broken image.

The current SVG placeholders are generated by `npm run generate:placeholders` (`scripts/generate-placeholders.mjs`). Once real assets exist you can delete the generated SVGs; do **not** re-run the script afterwards, since it overwrites `cover.svg` / `screenshot-0N.svg` files.

## 6. Deploy to Vercel

> The repository must be **public** for collaborators' commits to deploy on Vercel's free Hobby plan (Hobby does not support collaboration on private repositories). The site is marked `noindex` and `robots.txt` disallows crawling, so it is shared by link only.
>
> Every build runs `npm run check:content` first: if someone's content is invalid, the build fails and the previous version stays live. GitHub Actions (`.github/workflows/check.yml`) runs the same checks on every push and pull request.

1. Push this repository to GitHub/GitLab/Bitbucket.
2. In Vercel, **Add New → Project**, import the repository. Framework preset: **Next.js** (auto-detected). No environment variables are required.
3. Deploy. Every push to the main branch redeploys; pull requests get preview URLs.

Or with the CLI:

```bash
npm i -g vercel
vercel          # preview deployment
vercel --prod   # production deployment
```

Optional: set `NEXT_PUBLIC_SITE_URL` (e.g. `https://showcase.example.com`) when using a custom domain so Open Graph URLs are absolute. On Vercel the production URL is detected automatically.

## Accessibility & motion

- `prefers-reduced-motion` disables the intro, parallax, scroll-scrub and particle animation, and shows every section in its final readable state.
- Touch devices use native scrolling and get simplified interactions with no hover dependency.
- Everything interactive is keyboard accessible. In the Project Universe, Tab or the arrow keys move between nodes, Enter/Space opens a preview, and Esc closes it.
